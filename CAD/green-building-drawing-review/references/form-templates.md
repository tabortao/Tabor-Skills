# 审图记录单模板结构（填表前必须先解析）

## 通用网格坐标

各专业模板均为 **11 列网格**，`doc_set_table_cells` 用 1-based 网格坐标：

| col | 内容 |
|---|---|
| 1 | 图号 |
| 3 | 校审意见 |
| 7 | 差错分类 · 强条 |
| 8 | 差错分类 · 法规 |
| 9 | 差错分类 · 图面 |
| 10 | 处理（**留空**，待设计人回复） |
| 11 | 验证（**留空**） |
| 3 (row1) | 项目名称 |
| 7 (row1) | 设计号 |
| 3 (row2) | 旧项目信息，**清空** |
| 2 / 5 / 8 (签署行) | 审核人+日期 / 设计人 / 校对人 |

模板「专业」行已预勾本专业，无需修改。

## 各专业行数（**不同专业不同，必须先跑 `inspect_form.py`**）

| 专业 | 总行数 | 意见行 | 小计行 | 签署行 | 意见容量 |
|---|---|---|---|---|---|
| 建筑 | 36 | row 7~34 | row 35 | row 36 | 28 |
| 给排水 | 18 | row 7~16 | row 17 | row 18 | 10 |
| 暖通 | 23 | row 7~21 | row 22 | row 23 | 15 |
| 电气 | 23 | row 7~21 | row 22 | row 23 | 15 |
| 结构 | 23（待本项目模板复核） | row 7~21 | row 22 | row 23 | 15 |
| 景观 / 幕墙 / 智能化 | **未知，必须解析** | — | — | — | — |

暖通 / 电气 / 结构模板的行列与合并结构完全一致，可复用同一套 layout。

> `inspect_form.py` 通过「小计」「图号 / 校审意见」表头行自动推断 `opinion_first_row` / `opinion_last_row` / `subtotal_row` / `sign_row`。**任何新专业、新模板都不要硬编码行号**。意见条数超过容量时脚本会报错，需分页或删减。

## 小计与签署

- 小计行：`col7 = 强条数`、`col8 = 法规数`、`col9 = 图面数`，`col10/11` 清空。
- 签署行：`col2 = "审核人            日期"`，`col5` / `col8` 默认留 `"            年 月  日"`（给排水/暖通/电气口径）；建筑用户最终版为空，可用 `--sign-blank`。
- 模板旧意见行、旧「已修改 / ✓」、旧处理/验证栏：**必须逐行清空**，包括未用到的意见行。

## 图号规则

- **按本项目图纸目录的真实编号填写**，不要沿用模板旧项目的图号。
- 已验证格式：建筑 `0-AW-0001~0005`；给排水 `0-PW-0001~0009`；电气 `0-EW-0001~0003`；暖通本项目为 `MW-00003~00013`（5 位、无 `0-` 前缀，而参考模板旧项目写 `0-MW-0004`）。
- 无法定位到具体图号时写 `——` 或「总图 / 构造做法表 / 系统图」等部位名，不要编造编号。

## 表格行数：默认不动

生成时**保留模板原行数**，不要主动删空行。用户最终版会按版面自行删减，但各专业留白不一致（建筑删光、给排水留 2 行、电气留 4 行、暖通未动），没有统一规律。仅在用户明确要求收表时用 `trim_rows.py` 指定 `--keep-blank`，填表保存后从大到小逐行删。

## 成品命名与位置

```
<项目根目录>/<YYYYMMDD> 审图记录单-施工图-绿建提<专业>.docx
```

例：`20261109 审图记录单-施工图-绿建提给排水.docx`。与建筑专业保持同一目录、同一日期前缀。

## 校验（`verify_form.py`）

成品必须复核：意见条数、每行分类勾选、小计一致性、处理/验证列为空、表头项目名与设计号、无旧项目信息残留、`word/media` 图片数（对比模板，判断是否误删内嵌限值表截图）。
