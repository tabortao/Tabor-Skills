# 绿色专篇 CAD 版 —— 经验库

> 记录实测参数、踩过的坑、各项目档案。每做完一单，把新踩的坑和实际用的参数补进来。

## 一、环境与调用链

| 项 | 值 |
|---|---|
| CAD | AutoCAD 2022 + 天正 T30（`app.Name` 返回「天正软件 24.1s (LMS Tech)」，窗口类名 `AfxMDIFrame140u`） |
| Python | `D:/Code/Python/multiCAD-mcp/.venv/Scripts/python.exe`（自带 pywin32 / PIL） |
| 字体 | `GB-标准` = `gbenor.shx` + `gbcbig.shx`；图签沿用图框自带「宋体」样式 |
| 图层 | `GB-TEXT`(色7 正文) / `GB-HEAD`(色5 标题) / `GB-TABLE`(色8 表格线) |

**为什么不用 multiCAD-mcp 工具**：该 MCP 是 stdio 进程，一次 kill 后当前会话不会自动重连
（工具报 Not connected），改 mcp.json 也不触发重载。它的 `adapter_manager.py` 里 `cad_priorities`
原为 ZWCAD 优先，已改为 AutoCAD 优先。结论：**直接走 COM 更稳**，MCP 适合做一次性探查。

## 二、COM 硬约束（违反必崩）

1. **点参数**必须 `VARIANT(pythoncom.VT_ARRAY|pythoncom.VT_R8, [x,y,z])`，普通 tuple/list 会被拒绝。
2. **对象数组**（CopyObjects）必须 `VARIANT(pythoncom.VT_ARRAY|pythoncom.VT_DISPATCH, objs)`。
   复制后无法直接拿到新对象 → 用 `ms.Count` 变化 + 后段索引范围定位，或 Handle 差集。
3. **不能 COM Close 文档**：`doc.Close()` 会让天正整体断连（后续所有调用 `<unknown>`）。
   关图只能 `doc.SendCommand("_.CLOSE\n")`；并且**永远保留至少一个文档**（关掉最后一个也断连）。
4. **Application 句柄会失效**：文档增删后旧句柄报 `<unknown>.Count`，每次操作前重新
   `win32.GetActiveObject("AutoCAD.Application")`，并 `try/sleep/retry`（RPC 会短暂拒收，实测最长 90s）。
5. `doc.Saved` 不可写（报 can not be set）；只读属性的保存只能 `doc.Save()`。
6. **新建 MTEXT 默认字高 350**（继承系统 TEXTSIZE）。必须显式 `m.Height = 3.5` 并读回校验，
   否则包围盒高度十几万毫米，排版直接爆页、页数飙到上百。
7. **`AttachmentPoint = 5`（正中）不可靠**：COM 里把设置的插入点当左上角，文字整体右移半宽。
   要居中就建完 `GetBoundingBox()` 再 `Move` 到目标中心。
8. **文案里带 `\\`、`{`、`}` 要转义**为 `\\\\`、`\\{`、`\\}`，否则 MTEXT 报格式错误。
9. **沙箱里 `os.remove` 会转回收站**，被 CAD 占用的 dwg 删不掉 → 先 `SendCommand("_.CLOSE")`
   再 `shutil.copy2` 覆盖，别依赖 remove 成功。

```
X0=30  X1=740  GUT=8   →  栏宽 CW=(740-30-16)/3 = 231.33mm
```

- **一栏约 40 个汉字宽**：761 段正文 833 段/4 万字在 5 页 A1 排完，页 1~4 三栏全满。
- 字距：全角 1.0×字高、半角 0.55×字高（估算残留误差用 GetBoundingBox 兜底）。

## 四、踩过的坑（按严重程度）

### 1. 按索引批量删除 → 删错对象（血案）
症状：写脚本「收集 y>568 的页眉 MTEXT 下标」→ 升序逐个 `ms.Item(i).Delete()`。
删掉第 3120 号后，3121 号变成原 3122 号，于是第 2、4 页的页码没删、第 3、5 页的
**图签文字**（子项名称）被误删。
正确做法：**扫一条→删一条→重新扫**（`while True: 找到第一个 → Delete → 重扫`），或者
干脆重新生成整张图。禁止按索引列表批量删。

### 2. MTEXT 不会在超长 ASCII 串内折行
实测：300 字符连续英文/数字放进 30mm 宽的 MTEXT，仍然只占 1 行、横向穿出栏外。
→ 必须在 `make_layout.py` 生成阶段按列宽插 `\P` 硬断（`wrap_cell()`），不能指望 CAD 自动折。

### 3. 宽表跨整幅会翻倍页数
13 列评分表最窄列只有 8mm，原设计让列数 ≥9 或最窄列 <11mm 就跨整幅 3 栏。
代价：16 个宽表各让一整页留白，6 页 → **17 页**。结论 `--span` 默认关闭，
真要开就接受页数翻倍，或把宽表单独做附表页。

### 4. 合并块整块跳栏留白 150~550mm
833 段合并成 239 块后，一块最高 54 段（约 300mm），栏底剩 100mm 时整块跳走 → 栏底大片空白。
→ 二分查找「放得下的段落前缀」：改 `m.TextString` 后 `GetBoundingBox` 立即更新，
3 段→2 段→1 段高度即时变化，只把放得下的留在本栏。本机 8 个块被切分，页 1~4 栏底全部填满。

### 5. 校验要按 bbox 判栏位，不能按插入点
表格单元格的插入点在左边界，按插入点算会判到隔壁栏，出现 380+ 条假越界。
→ 一律用 `GetBoundingBox()` 的 x1 与「该栏右边界」比。

### 6. 截图截错窗口
天正窗口最小化时 `GetWindowRect` 返回 `(-32000,-32000,…)`，`SetForegroundWindow` 无效，
截图会抓到别的程序。→ 先 `ShowWindow(SW_RESTORE)` + `SW_SHOWMAXIMIZED` 再抓；
`EnumWindows` 按类名 `AfxMDIFrame` 找主窗口。
